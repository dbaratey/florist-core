# Технологический стек

## Обзор

Этот документ описывает технологический выбор для `florist-core` и обоснование каждого решения.

## Бэкенд

### Язык и среда выполнения

- **Go 1.24+**
    - **Почему**: Простота, отличная поддержка параллелизма, быстрая компиляция, сильная стандартная библиотека.
    - **Преимущества**: Единый бинарный файл для развертывания, низкое потребление памяти, отличные инструменты.
    - **Компромиссы**: Менее выразительный, чем некоторые языки, но обеспечивает ясность и поддерживаемость.

### HTTP Framework

- **chi v5** (`github.com/go-chi/chi/v5`)
    - **Почему**: Легковесный, идиоматичный Go, компонуемое middleware, роутинг на основе контекста.
    - **Рассмотренные альтернативы**: Gin (слишком много "магии"), Echo (похож на chi, но менее идиоматичен).
    - **Преимущества**: Минимальные зависимости, RESTful роутинг, отличная производительность.

### База данных

- **PostgreSQL 15+**
    - **Почему**: ACID-транзакции, надежная поддержка SQL, JSON-колонки, отличная производительность.
    - **Варианты использования**:
        - Транзакционные данные (заказы, партии)
        - Таблица событий Outbox
        - Будущее: JSONB для гибких атрибутов продуктов
    - **Пул соединений**: `pgx/v5` (нативный драйвер PostgreSQL)

### Миграции базы данных

- **SQL-first миграции** (чистые `.sql` файлы в `/migrations`)
    - **Почему**: Прямой контроль, отсутствие абстракции ORM, легкость ревью кода.
    - **Инструмент**: Ручное выполнение на данный момент; в будущем: `golang-migrate` или `goose`.
    - **Соглашение**: Файлы с префиксами версий (например, `001_create_inventory.up.sql`).

### Логирование

- **slog** (стандартная библиотека Go, Go 1.21+)
    - **Почему**: Структурированное логирование, стандартная библиотека, ноль зависимостей.
    - **Формат**: JSON для продакшена, текст для разработки.
    - **Уровни**: INFO (по умолчанию), ERROR, DEBUG (через конфиг).

### Тестирование

- **testing** (стандартная библиотека Go)
    - **Unit-тесты**: Доменная логика, обработчики вариантов использования.
    - **Интеграционные тесты**: HTTP-обработчики, реализации репозиториев (с тестовой БД).
    - **Test doubles**: Интерфейсы для репозиториев, без фреймворков для моков.

## Инфраструктура

### Контейнеризация

- **Docker + docker-compose**
    - **Локальная разработка**: PostgreSQL, Redis (в будущем).
    - **Dockerfile**: Многоэтапная сборка (builder + distroless финальный образ).

### Развертывание (В будущем)

- **Цель**: Docker + Kubernetes или простой VPS с systemd.
- **Конфигурация**: Переменные окружения через `.env` или секреты K8s.
- **Health checks**: Эндпоинт `/healthz`.

## Фронтенд (В планах)

- **VueJS 3 (Composition API)**
    - **Почему**: Реактивность, отличная документация, высокая скорость разработки.
    - **State Management**: Pinia.
    - **UI Framework**: Tailwind CSS или Element Plus.

## Кэширование (В планах)

- **Redis**
    - **Использование**: Кэширование каталога, брокер для Outbox событий.
    - **Почему**: Высокая производительность, поддержка различных структур данных.
