# Доменная логика

## Обзор

Этот документ описывает ключевую бизнес-логику и правила florist-core ERP системы для флористических магазинов.

## Bounded Contexts

### Ordering Context (Контекст заказов)

Ответственен за управление жизненным циклом заказов от создания до выполнения.

#### Aggregate: Order

**Инварианты:**
- Заказ должен иметь минимум 1 позицию
- Общая сумма заказа > 0
- Статус заказа может изменяться только в определенной последовательности
- Заказ не может быть удален после начала выполнения

**Статусы заказа:**
1. `Draft` - Черновик (может быть изменен/удален)
2. `Confirmed` - Подтвержден (отправлен в работу)
3. `InProgress` - В работе (сборка букета)
4. `Ready` - Готов к выдаче
5. `Completed` - Выполнен
6. `Cancelled` - Отменен

**Бизнес-правила:**
- Переход Draft → Confirmed: проверка наличия всех позиций на складе
- Переход Confirmed → InProgress: резервирование товаров
- Переход InProgress → Ready: подтверждение сборки
- Переход Ready → Completed: подтверждение выдачи клиенту
- Отмена возможна только из статусов Draft, Confirmed

**Domain Events:**
- `OrderCreated` - Заказ создан
- `OrderConfirmed` - Заказ подтвержден
- `OrderItemAdded` - Позиция добавлена
- `OrderItemRemoved` - Позиция удалена
- `OrderStatusChanged` - Статус изменен
- `OrderCompleted` - Заказ выполнен
- `OrderCancelled` - Заказ отменен

#### Value Objects

**OrderItem:**
- ProductID (UUID)
- Quantity (целое > 0)
- Price (Money, >= 0)
- Subtotal (вычисляемое: Quantity × Price)

**Money:**
- Amount (int64, копейки)
- Currency (строка, по умолчанию "RUB")

### Inventory Context (Контекст инвентаря)

Управляет складскими операциями: приемка, списание, инвентаризация.

#### Aggregate: Batch (Партия товара)

**Инварианты:**
- Партия содержит товары одного типа
- Количество товара >= 0
- Дата поступления <= текущей даты
- Срок годности > даты поступления (для скоропортящихся товаров)

**Жизненный цикл:**
1. `Pending` - Ожидается поставка
2. `Received` - Получена
3. `Available` - Доступна для продажи
4. `Reserved` - Зарезервирована
5. `Sold` - Продана
6. `Expired` - Просрочена
7. `Disposed` - Списана

**Бизнес-правила:**
- При создании заказа товары резервируются из самой старой доступной партии (FIFO)
- Партии с истекающим сроком годности помечаются для приоритетной продажи
- Автоматическое списание просроченных товаров

**Domain Events:**
- `BatchReceived` - Партия получена
- `BatchReserved` - Партия зарезервирована
- `BatchReleased` - Резерв снят
- `BatchSold` - Партия продана
- `BatchExpired` - Срок годности истек
- `BatchDisposed` - Партия списана

#### Value Objects

**StockLevel:**
- ProductID
- TotalQuantity
- AvailableQuantity
- ReservedQuantity

### Catalog Context (Контекст каталога)

Управляет информацией о продуктах и категориях.

#### Aggregate: Product (Товар)

**Инварианты:**
- Уникальное имя товара
- Цена >= 0
- SKU уникален в системе
- Категория должна существовать

**Типы товаров:**
1. `Flower` - Цветы (роза, тюльпан, и т.д.)
2. `Greenery` - Зелень (эвкалипт, папоротник)
3. `Accessory` - Аксессуары (лента, упаковка)
4. `Supply` - Расходные материалы (оазис, проволока)

**Бизнес-правила:**
- Цветы имеют срок годности (обязательно)
- Аксессуары и материалы - длительное хранение
- Минимальный остаток для автоматического заказа у поставщика

**Domain Events:**
- `ProductCreated`
- `ProductUpdated`
- `ProductPriceChanged`
- `ProductArchived`

## Интеграция между контекстами

### Order → Inventory

При подтверждении заказа:
1. Order Context публикует `OrderConfirmed` event
2. Inventory Context подписан на этот event
3. Inventory резервирует товары через `ReserveStock` команду
4. При успехе публикует `StockReserved` event
5. Order Context получает подтверждение резервирования

### Inventory → Catalog

При низком уровне запасов:
1. Inventory Context проверяет StockLevel
2. Если AvailableQuantity < MinimumLevel
3. Публикует `LowStockDetected` event
4. Catalog Context может инициировать создание заказа поставщику

## Бизнес-правила верхнего уровня

### Ценообразование

- Цена товара может меняться, но не влияет на уже созданные заказы
- Скидки применяются на уровне заказа, не на уровне товара
- Сезонные наценки (например, перед 8 марта)

### Управление запасами

- FIFO (First In, First Out) для скоропортящихся товаров
- Автоматическое списание товаров с истекшим сроком годности
- Пороговые значения для автоматического заказа

### Рабочий процесс заказа

1. Клиент создает заказ → статус Draft
2. Флорист проверяет и подтверждает → Confirmed
3. Система резервирует товары на складе
4. Флорист начинает сборку букета → InProgress
5. Букет собран → Ready
6. Клиент забирает заказ → Completed

### Обработка отмен

- Отмена из Draft: просто удаляется
- Отмена из Confirmed: снимается резерв товаров
- Отмена из InProgress/Ready: требует подтверждения менеджера

## Специфичные для флористики правила

### Срок годности цветов

- Розы: 7-10 дней
- Тюльпаны: 5-7 дней
- Хризантемы: 10-14 дней
- Зелень: 5-7 дней

### Сезонность

- Пиковые периоды: 8 марта, 14 февраля, День учителя
- Увеличенные запасы за 2 недели до пикового дня
- Специальные предложения после пиковых дней

### Композиции

- Букет может состоять из нескольких видов цветов
- Каждый компонент списывается отдельно со склада
- Готовые букеты также могут храниться на складе

## Отчеты и аналитика

### Ключевые метрики

- Оборачиваемость запасов
- Процент просроченных товаров
- Средний чек
- Популярные товары
- Выручка по периодам

### Предупреждения

- Низкий уровень запасов
- Товары с истекающим сроком годности
- Неподтвержденные заказы старше 24 часов
